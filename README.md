# Gestão Ágil de Projetos: Scrum, Git e GitHub para Trabalho em Equipe

Curso ministrado na **UNESP** em 2026 pelo professor **Orlando Saraiva Jr**, com o objetivo de apresentar os fundamentos da gestão de projetos, a gestão ágil com **Scrum** e o uso de **Git**, **GitHub** e **GitHub Desktop** para organizar o trabalho em equipe.

O curso foi pensado para um público que não é necessariamente da área de computação: as ferramentas são apresentadas por meio de analogias e usadas pela interface gráfica do GitHub Desktop, sem linha de comando. Cada aula termina com uma atividade prática (*hands on*).

## Conteúdo trabalhado

### Aula 1: Projetos e gestão de projetos

- **O que é um projeto:** uma sequência de atividades únicas, complexas e interconectadas, com um objetivo específico, que deve ser concluída dentro do prazo, do orçamento e de acordo com as especificações.
- **Características de um projeto:** sequência de atividades, atividades únicas, atividades complexas, atividades conectadas, um único objetivo, tempo determinado, orçamento limitado e especificações definidas.
- **Triângulo de Ferro (Tríplice Restrição):** a relação entre tempo, custo e escopo.
- **Triângulo de Escopo:** escopo, qualidade, custo, tempo, recursos e risco.
- **Gestão tradicional (cascata/waterfall):** planejamento antecipado, fases sequenciais, vantagens (previsibilidade, documentação, controle) e desvantagens (pouca flexibilidade, feedback tardio, risco concentrado).
- **Gestão ágil:** ciclos curtos (sprints), entregas frequentes, participação do cliente, vantagens e desvantagens.
- **Manifesto Ágil:** seus quatro valores.
- **Quando usar cada abordagem:** a tradicional fixa o escopo, enquanto a ágil fixa tempo e custo e ajusta o escopo a cada ciclo.

### Aula 2: Scrum, Git e GitHub

- **Metodologias ágeis** e a origem do **Scrum** (Ken Schwaber e Jeff Sutherland, OOPSLA 1995).
- **Papéis do Scrum:** Product Owner, Scrum Master e Equipe de Desenvolvimento.
- **Atividades e artefatos do Scrum:** Backlog do Produto, Sprints, Sprint Planning, Sprint Backlog, execução da Sprint, Daily Scrum, Revisão da Sprint e Retrospectiva da Sprint.
- **O problema do controle de versão:** o caso do `trabalho_final_AGORA_SIM.zip`.
- **Git, GitHub Desktop e GitHub:** o Git é o motor (o "save" de videogame), o GitHub Desktop é o painel de controle e o GitHub é a garagem na nuvem.
- **Vocabulário:** repositório, commit, histórico/log, clone, push e pull.
- **Aplicações práticas:** versionar documentos, atas, roteiros e fotos do processo e de protótipos.

### Aula 3: Contribuição colaborativa com Fork e Pull Request

- **Revisão:** repositório, commit, clone, push e pull.
- **Contribuir com projetos de outras pessoas:** por que não é possível dar push direto em um repositório alheio.
- **Fork:** uma cópia do repositório na sua própria conta.
- **Pull Request (PR):** um pedido formal para que o dono do projeto incorpore suas mudanças.
- **Boas práticas de PR:** título claro, descrição do que mudou e por quê, mudanças pequenas e commits com mensagens significativas.
- **Conflitos:** como surgem, como resolvê-los no GitHub Desktop e como evitá-los.
- **PRs dentro do Scrum:** itens do Sprint Backlog viram PRs, a revisão de código faz parte da Definição de Pronto e os PRs aceitos são apresentados na Revisão da Sprint.
- **Por que isso importa:** organização do trabalho em equipe, revisão, histórico de contribuições e portfólio em projetos de código aberto.
